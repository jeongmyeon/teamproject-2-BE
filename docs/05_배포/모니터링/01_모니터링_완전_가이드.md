## Spring Boot 메트릭 활성화

### 1. Prometheus 어노테이션 추가

모든 Spring Boot 서비스에 어노테이션 추가:

```bash
# biddy 네임스페이스의 모든 서비스에 일괄 적용
for service in discovery config apigateway member product order auction payment; do
  kubectl patch deployment $service -n biddy --type='json' -p='[
    {
      "op": "add",
      "path": "/spec/template/metadata/annotations",
      "value": {
        "prometheus.io/scrape": "true",
        "prometheus.io/port": "8080",
        "prometheus.io/path": "/actuator/prometheus"
      }
    }
  ]'
done
```

### 2. Spring Boot 설정 확인

각 서비스의 `application.yml`에 다음 설정이 있는지 확인:

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus
  metrics:
    export:
      prometheus:
        enabled: true
```

### 3. 메트릭 확인

```bash
# 서비스 Pod 이름 확인
kubectl get pods -n biddy

# 메트릭 엔드포인트 확인
kubectl exec -n biddy <pod-name> -- wget -qO- http://localhost:8080/actuator/prometheus | head -20
```

## 주요 메트릭 확인

### Prometheus에서 직접 쿼리

`http://<워커노드-IP>:30090` 접속 → Graph 탭

#### 1. 실시간 CPU 사용률

```promql
# 노드별 CPU 사용률 (%)
100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) by (instance) * 100)

# Pod별 CPU 사용률
sum(rate(container_cpu_usage_seconds_total{namespace="biddy"}[5m])) by (pod) * 100
```

#### 2. 실시간 메모리 사용률

```promql
# 노드별 메모리 사용률 (%)
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100

# Pod별 메모리 사용량 (MB)
sum(container_memory_working_set_bytes{namespace="biddy"}) by (pod) / 1024 / 1024
```

#### 3. 실시간 디스크 사용률

```promql
# 디스크 사용률 (%)
100 - ((node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100)
```

#### 4. 실시간 네트워크 트래픽

```promql
# 네트워크 수신 속도 (MB/s)
sum(rate(node_network_receive_bytes_total[5m])) by (instance) / 1024 / 1024

# 네트워크 송신 속도 (MB/s)
sum(rate(node_network_transmit_bytes_total[5m])) by (instance) / 1024 / 1024
```

#### 5. 실시간 Pod 상태

```promql
# Running 상태의 Pod 수
count(kube_pod_status_phase{namespace="biddy", phase="Running"})

# Pod 재시작 횟수
kube_pod_container_status_restarts_total{namespace="biddy"}
```

#### 6. 실시간 HTTP 요청 (Spring Boot)

```promql
# 초당 요청 수
sum(rate(http_server_requests_seconds_count{namespace="biddy"}[5m])) by (uri)

# 평균 응답 시간 (ms)
rate(http_server_requests_seconds_sum{namespace="biddy"}[5m]) / rate(http_server_requests_seconds_count{namespace="biddy"}[5m]) * 1000
```

#### 7. 실시간 JVM 메트릭

```promql
# JVM Heap 사용률 (%)
(jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}) * 100

# GC 시간
rate(jvm_gc_pause_seconds_sum[5m])
```

## 실시간 모니터링 FAQ

### Q1: emptyDir 사용해도 실시간 모니터링 가능한가요?

**A: 네, 완벽하게 가능합니다!**

- ✅ Pod가 실행 중인 동안 계속 메트릭 수집
- ✅ CPU, 메모리, 디스크, 네트워크 모두 실시간 측정
- ✅ Prometheus가 15초마다 자동 수집
- ✅ Grafana에서 실시간 그래프로 확인
- ⚠️ **유일한 차이점**: Pod 재시작 시 과거 데이터만 삭제

### Q2: 데이터는 얼마나 보관되나요?

**A: 2시간 동안 보관됩니다.**

```yaml
# Prometheus 설정
--storage.tsdb.retention.time=2h  # 2시간 보관
```

Pod가 재시작되지 않으면 계속 누적됩니다.

### Q3: 과거 데이터는 언제 삭제되나요?

**A: Pod가 재시작될 때만 삭제됩니다.**

- Pod 정상 실행 중: 데이터 계속 누적
- Pod 재시작 시: 모든 데이터 삭제
- 테스트 서버에서는 문제 없음

### Q4: EBS 버전과 성능 차이가 있나요?

**A: 실시간 모니터링 성능은 동일합니다.**

| 기능 | emptyDir | EBS (PVC) |
|------|----------|-----------|
| 실시간 CPU 측정 | ✅ 동일 | ✅ 동일 |
| 실시간 메모리 측정 | ✅ 동일 | ✅ 동일 |
| 실시간 네트워크 측정 | ✅ 동일 | ✅ 동일 |
| 과거 데이터 분석 | ❌ Pod 재시작 시 삭제 | ✅ 30일 보관 |
| 비용 | $0 | $3/월 |

## 문제 해결

### 문제 1: Pod가 Pending 상태

**증상:**
```bash
kubectl get pods -n monitoring
# STATUS: Pending
```

**해결:**
```bash
# 원인 확인
kubectl describe pod <pod-name> -n monitoring

# 리소스 부족인 경우 → 메모리 제한 축소
kubectl patch deployment prometheus -n monitoring --type='json' -p='[
  {
    "op": "replace",
    "path": "/spec/template/spec/containers/0/resources/limits/memory",
    "value": "256Mi"
  }
]'
```

### 문제 2: Grafana에서 "No Data" 표시

**증상:**
```
대시보드에 "No Data" 또는 "N/A" 표시
```

**해결:**
```bash
# 1. Prometheus 정상 동작 확인
kubectl logs -n monitoring deployment/prometheus

# 2. Prometheus UI에서 직접 확인
# http://<워커IP>:30090 → Graph → 쿼리: up

# 3. Grafana Datasource 테스트
# Grafana → Configuration → Data Sources → Prometheus → Test
```

### 문제 3: Node Exporter 메트릭 없음

**증상:**
```
Prometheus Targets에서 "Context deadline exceeded" 에러
```

**해결:**
```bash
# DaemonSet 로그 확인
kubectl logs -n monitoring daemonset/node-exporter

# 각 노드에서 실행 중인지 확인
kubectl get pods -n monitoring -l app=node-exporter -o wide

# hostNetwork, hostPID 권한 확인
kubectl get daemonset node-exporter -n monitoring -o yaml | grep -A 2 "hostNetwork\|hostPID"
```

### 문제 4: Spring Boot 메트릭 수집 안됨

**증상:**
```
Prometheus에서 Spring Boot 메트릭이 보이지 않음
```

**해결:**
```bash
# 1. 어노테이션 확인
kubectl get pod <pod-name> -n biddy -o yaml | grep prometheus

# 2. Actuator 엔드포인트 확인
kubectl exec -n biddy <pod-name> -- wget -qO- http://localhost:8080/actuator/prometheus

# 3. 어노테이션 재적용
kubectl patch deployment <service-name> -n biddy --type='json' -p='[...]'
```

## 모니터링 Best Practices

### 1. 실시간 알림 설정

Grafana에서 Alert 설정:

1. 대시보드 Panel 편집
2. Alert 탭 클릭
3. 조건 설정 (예: CPU > 80%)
4. Notification 채널 설정 (이메일, Slack 등)

### 2. 주요 메트릭 주시

**즉시 대응 필요:**
- Pod Down (5분 이상)
- CPU 90% 이상 (10분 이상)
- 메모리 90% 이상 (10분 이상)
- 디스크 90% 이상

**주의 관찰:**
- CPU 80% 이상 (10분 이상)
- 메모리 80% 이상 (10분 이상)
- 높은 응답 시간 (1초 이상)

### 3. 대시보드 구성 추천

```
1. Overview 대시보드
   - 전체 시스템 상태 한눈에

   - 실시간 업데이트

2. 서비스별 대시보드
   - Auction, Member 등 개별 서비스
   - HTTP 요청, JVM, 응답 시간
   - 실시간 그래프

3. 인프라 대시보드
   - 노드 리소스
   - 네트워크, 디스크 I/O
   - 실시간 추세
```

## 실시간 모니터링 FAQ

### Q: emptyDir 사용해도 실시간 측정 가능한가요?

**A: 네, 완벽하게 가능합니다!**

✅ CPU, 메모리, 디스크, 네트워크 모두 실시간 측정 (15초마다)
✅ Pod가 실행 중인 동안 계속 메트릭 수집
✅ Grafana에서 실시간 그래프로 확인
⚠️ 유일한 차이점: Pod 재시작 시 과거 데이터 삭제

### Q: 측정 가능한 모든 메트릭은?

**A: 다음 모든 메트릭 실시간 측정 가능:**

- ✅ **CPU**: 코어별 사용률, 전체 사용률
- ✅ **메모리**: 사용량, 여유량, 캐시
- ✅ **디스크**: I/O, 사용률, 읽기/쓰기 속도
- ✅ **네트워크**: 수신/송신 속도, 패킷 수
- ✅ **Pod**: 상태, 재시작 횟수
- ✅ **애플리케이션**: HTTP 요청, JVM, 응답 시간

### Q: EBS 없으면 메트릭 수집 안되나요?

**A: 아니요, EBS와 메트릭 수집은 무관합니다!**

- EBS는 데이터 **영구 보관**용
- 메트릭 수집은 emptyDir에서도 **완벽 동작**
- 실시간 모니터링 성능 **동일**

Spring Boot 애플리케이션에서 Prometheus 메트릭을 노출하려면 **소스 코드 변경**이 필요합니다.

**상세 가이드**: `docs/05_배포/Spring_Boot_Prometheus_설정_가이드.md`

#### 필수 변경사항 요약

**1. build.gradle 수정 (모든 서비스)**
```gradle
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-actuator'  // 이미 있음
    implementation 'io.micrometer:micrometer-registry-prometheus'  // ⬅️ 추가
}
```

**2. application.yml 수정 (모든 서비스)**
```yaml
management:
  endpoints:
    web:
      exposure:
        include: health, info, metrics, prometheus  # prometheus 추가
  metrics:
    export:
      prometheus:
        enabled: true
```

**3. 재빌드 및 재배포**
```bash
# Git commit & push
git add .
git commit -m "feat: Add Prometheus metrics support"
git push

# Kubernetes에서 재배포 (Docker 이미지 재빌드 후)
kubectl rollout restart deployment member -n biddy
# ... (모든 서비스 동일하게)
```
