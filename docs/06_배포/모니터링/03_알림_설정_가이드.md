# 알림(Alert) 설정 가이드

> Slack/Discord로 서버 장애, 메모리 부족, 에러 급증 알림 받기

**소요 시간:** 10분
**업데이트:** 2026-07-22

---

## 🚨 자동 설정된 Alert Rules

모니터링 시스템에는 **10개의 알림 규칙**이 자동으로 설정되어 있습니다.

### Critical (즉시 대응 필요)

| Alert | 조건 | 대기 시간 | 설명 |
|-------|------|-----------|------|
| **PodDown** | Pod Up == 0 | 2분 | 서비스 완전 중단 |
| **HighErrorRate** | 5xx 에러율 > 5% | 3분 | API 에러 급증 |
| **NodeMemoryPressure** | Worker 메모리 > 95% | 5분 | 노드 메모리 한계 |
| **PrometheusNotReady** | Prometheus Down | 2분 | 모니터링 시스템 중단 |

### Warning (모니터링 필요)

| Alert | 조건 | 대기 시간 | 설명 |
|-------|------|-----------|------|
| **HighMemoryUsage** | Pod 메모리 > 90% | 5분 | Pod 메모리 부족 |
| **HighCpuUsage** | Pod CPU > 90% | 5분 | Pod CPU 과부하 |
| **HighLatency** | 응답시간 > 1초 | 5분 | API 응답 지연 |
| **HighDiskUsage** | 디스크 > 90% | 5분 | 디스크 공간 부족 |
| **PrometheusTargetDown** | Target Down | 3분 | 메트릭 수집 실패 |
| **GrafanaDown** | Grafana Down | 2분 | 대시보드 접속 불가 |

## 📋 1단계: Alert 확인

### Prometheus에서 Alert 상태 확인

```bash
# 브라우저에서 접속
http://<worker-ip>:30090/alerts
```

**Alert 상태**:
- 🟢 **INACTIVE**: 정상 (조건 미충족)
- 🟡 **PENDING**: 대기 중 (조건 충족, 대기 시간 경과 전)
- 🔴 **FIRING**: 알림 발생 중 (대기 시간 경과 후)

### kubectl로 Alert Rules 확인

```bash
# Master 노드에서 실행
kubectl get configmap -n biddy-monitoring prometheus-alert-rules -o yaml
```

## 📱 2단계: Slack 연동

### 2-1. Slack Webhook URL 발급

1. https://api.slack.com/apps 접속
2. **"Create New App"** 클릭
3. **"From scratch"** 선택
4. App 이름 입력: `Biddy Monitoring`
5. Workspace 선택
6. **"Incoming Webhooks"** 클릭
7. **Activate Incoming Webhooks** → ON
8. **"Add New Webhook to Workspace"** 클릭
9. 알림 받을 채널 선택 (예: #alerts)
10. **Webhook URL 복사**
    ```
    https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXX
    ```

### 2-2. Grafana에서 Slack 연동

#### 브라우저에서 Grafana 접속
```
http://<worker-ip>:30300
```

#### Alerting 설정
1. 왼쪽 메뉴: **Alerting** (종 아이콘)
2. **Contact points** 클릭
3. **Add contact point** 버튼 클릭

#### Slack Contact Point 추가
```
Name: Slack Alerts

Integration: Slack

Webhook URL: (위에서 복사한 URL 붙여넣기)
https://hooks.slack.com/services/T00000000/B00000000/XXXXXXXXXXXXXXXXXXXX

Title (Optional):
🚨 Biddy Monitoring Alert

(선택) Mention: @channel
(선택) Mention: @here
```

4. **Test** 버튼 클릭
   - Slack 채널에 테스트 메시지 수신 확인

5. **Save contact point** 클릭

### 2-3. Notification Policy 설정

1. **Alerting** → **Notification policies**
2. **Default policy** 옆 **Edit** (연필 아이콘)
3. **Contact point** → `Slack Alerts` 선택
4. **Update default policy**

## 💬 3단계: Discord 연동

### 3-1. Discord Webhook URL 발급

1. Discord 서버 설정 → **연동**
2. **웹후크** 클릭
3. **새 웹후크** 버튼
4. 웹후크 이름: `Biddy Monitoring`
5. 채널 선택 (예: #alerts)
6. **웹후크 URL 복사**
   ```
   https://discord.com/api/webhooks/1234567890/XXXXXXXXXXXXXXXXXXXX
   ```

### 3-2. Grafana에서 Discord 연동

#### Contact Point 추가
1. **Alerting** → **Contact points**
2. **Add contact point**

```
Name: Discord Alerts

Integration: Discord

Webhook URL: (위에서 복사한 URL 붙여넣기)
https://discord.com/api/webhooks/1234567890/XXXXXXXXXXXXXXXXXXXX

Message (Optional):
🚨 **Biddy Monitoring Alert**
{{ range .Alerts }}
- **{{ .Labels.alertname }}**: {{ .Annotations.summary }}
{{ end }}

(선택) Use Discord username: Biddy Bot
```

3. **Test** 버튼 → Discord 채널 확인
4. **Save contact point**

### 3-3. Notification Policy 업데이트

- Slack과 Discord 둘 다 받으려면:
  1. **Notification policies** → **Default policy Edit**
  2. **Additional contact points** → `Discord Alerts` 추가
  3. **Update**

## ✅ 4단계: 알림 테스트

### 방법 1: Pod 강제 종료 테스트

```bash
# Master 노드에서 실행

# 1. member 서비스 Scale Down (PodDown 알림 발생 예정)
kubectl scale deployment member -n biddy-services --replicas=0

# 2. 2분 대기
echo "Waiting 2 minutes for PodDown alert..."
sleep 120

# 3. Prometheus Alerts 확인
echo "Check: http://<worker-ip>:30090/alerts"

# 4. Slack/Discord에서 알림 수신 확인
# "PodDown: Pod member is down" 메시지 확인

# 5. 서비스 복구
kubectl scale deployment member -n biddy-services --replicas=1
```

**기대 결과**:
```
🚨 Biddy Monitoring Alert
- PodDown: Pod member-xxx-xxx is down
  Pod member-xxx-xxx in namespace biddy-services has been down for more than 2 minutes.
```

### 방법 2: 메모리 부하 테스트

```bash
# 특정 Pod에 메모리 부하 생성 (HighMemoryUsage 알림)
kubectl exec -it <pod-name> -n biddy-services -- sh -c '
  dd if=/dev/zero of=/tmp/memory.dat bs=1M count=500
'

# 5분 대기 후 Slack/Discord 확인
```

### 방법 3: Grafana 수동 테스트

1. Grafana → **Alerting** → **Contact points**
2. **Slack Alerts** 또는 **Discord Alerts** 옆 **Edit**
3. **Test** 버튼 클릭
4. Slack/Discord에서 테스트 메시지 수신 확인

## 🎛️ 5단계: Alert 커스터마이징 (선택)

### Alert 임계값 변경

Alert Rules는 ConfigMap에 정의되어 있습니다.

```bash
# Master 노드에서 실행
kubectl edit configmap prometheus-alert-rules -n biddy-monitoring
```

**예시: 메모리 임계값 90% → 85% 변경**
```yaml
- alert: HighMemoryUsage
  expr: (container_memory_working_set_bytes{namespace="biddy"} / container_spec_memory_limit_bytes{namespace="biddy"}) * 100 > 85  # 90 → 85
  for: 5m
```

저장 후 Prometheus 재시작:
```bash
kubectl rollout restart deployment prometheus -n biddy-monitoring
```

### 새로운 Alert 추가

```yaml
# 예시: 디스크 I/O 대기 시간 알림
- alert: HighDiskIOWait
  expr: rate(node_disk_io_time_seconds_total[5m]) > 0.8
  for: 10m
  labels:
    severity: warning
    team: infra
  annotations:
    summary: "High disk I/O wait on {{ $labels.instance }}"
    description: "Disk I/O wait time is high ({{ $value | humanize }})"
```

## 📊 6단계: Alert 대시보드 설정

### Grafana Alert Dashboard

1. **Dashboards** → **New** → **Import**
2. Dashboard ID 입력: `15282` (Prometheus Alerts Dashboard)
3. **Load** → **Import**

이 대시보드에서 모든 Alert 상태를 한눈에 확인 가능합니다.

## 🔕 7단계: 알림 음소거 (Silences)

### 일시적으로 알림 끄기

유지보수 중에는 알림을 일시적으로 끌 수 있습니다.

1. **Alerting** → **Silences**
2. **Add silence** 버튼
3. **Matchers** 설정:
   ```
   alertname = PodDown
   namespace = biddy-services
   ```
4. **Duration**: 1h (1시간)
5. **Comment**: "Maintenance work"
6. **Create**

## 🔧 문제 해결

### 알림이 오지 않음

#### 1. Prometheus Alerts 확인
```bash
# Alert가 FIRING 상태인지 확인
curl http://<worker-ip>:30090/alerts | grep -A5 "FIRING"
```

#### 2. Webhook URL 확인
```bash
# Grafana에서 Test 버튼 클릭
# 에러 메시지 확인
```

#### 3. Contact Point 로그 확인
```bash
kubectl logs -n biddy-monitoring deployment/grafana | grep -i "notification"
```

### Slack에서 메시지가 깨짐

Webhook URL이 정확한지 확인:
- ✅ 올바름: `https://hooks.slack.com/services/T.../B.../XXX`
- ❌ 잘못됨: URL에 공백 또는 줄바꿈 포함

### Discord 알림이 너무 많음

Notification Policy에서 **Grouping** 설정:
```
Group by: alertname, namespace
Group wait: 30s
Group interval: 5m
Repeat interval: 4h
```
