## 🎯 구조 이해하기

### 작업 흐름
```
1. Master 노드에서 kubectl 명령 실행 ✅
   ↓
2. Kubernetes가 자동으로 Worker 노드에 Pod 배포 ✅
   ↓
3. Worker 노드에서 Prometheus, Grafana 실행 ✅
```

### 현재 메모리 상황
```
Master: 2.4GB / 3.7GB (65% 사용) - kubectl 명령만 실행
Worker: 5.0GB / 7.6GB (66% 사용) - 애플리케이션 + 모니터링 실행
```

### Worker 배포 후 예상
```
Worker: 5.0GB → ~6.5-7GB (85-92%)
⚠️ 메모리 압박 예상 → Swap 추가 권장!
```

## 🚀 지금 바로 실행

### ⚠️ 중요: Swap 추가 먼저! (Worker 노드)

배포 전에 Worker 노드 메모리 부족 방지를 위해 Swap을 추가하세요.

```bash
# Worker 노드에 접속
ssh -i "your-key.pem" ubuntu@<worker-node-ip>

# Swap 생성 (2GB)
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 재부팅 후에도 유지
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 확인
free -h
# Swap: 2.0Gi 확인

# 작업 완료 후 로그아웃
exit
```

## 🔍 유용한 Prometheus 쿼리

Prometheus UI (`http://localhost:9090`) → Graph 탭

### 1. 서비스별 HTTP 요청 수
```promql
sum(rate(http_server_requests_seconds_count[5m])) by (application)
```

### 2. 평균 응답 시간 (ms)
```promql
rate(http_server_requests_seconds_sum[5m]) / rate(http_server_requests_seconds_count[5m]) * 1000
```

### 3. JVM Heap 메모리 사용률
```promql
(jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"}) * 100
```

### 4. CPU 사용률 (노드별)
```promql
100 - (avg(rate(node_cpu_seconds_total{mode="idle"}[5m])) by (instance) * 100)
```

### 5. 메모리 사용률 (노드별)
```promql
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100
```

## ⚠️ 문제 발생 시

### Pod가 Pending 상태로 멈춤

**확인**:
```bash
kubectl describe pod -n biddy-monitoring <pod-name>
```

**메시지에 "Insufficient memory" 표시 시**:

#### 해결 1: Master 노드에 Swap 추가 (권장)
```bash
# Master 노드에서 실행
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 재부팅 후에도 유지
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 확인
free -h
```

#### 해결 2: 리소스 제한 감소
```bash
# Prometheus 메모리 제한 축소
kubectl patch deployment prometheus -n biddy-monitoring --type='json' -p='[
  {
    "op": "replace",
    "path": "/spec/template/spec/containers/0/resources/limits/memory",
    "value": "1.5Gi"
  }
]'

# Grafana 메모리 제한 축소
kubectl patch deployment grafana -n biddy-monitoring --type='json' -p='[
  {
    "op": "replace",
    "path": "/spec/template/spec/containers/0/resources/limits/memory",
    "value": "768Mi"
  }
]'
```

### Grafana "No Data" 표시

**확인 1: Prometheus 로그**
```bash
kubectl logs -n biddy-monitoring -l app=prometheus
```

**확인 2: Prometheus Targets**
```bash
kubectl port-forward -n biddy-monitoring svc/prometheus 9090:9090
```

브라우저: `http://localhost:9090/targets`

**확인 3: Actuator 엔드포인트**
```bash
kubectl exec -n biddy-services <pod-name> -- curl localhost:8080/actuator/prometheus
```

## 🎯 다음 단계

### 1. 알림(Alert) 확인 ⭐ 중요!

모니터링 시스템에 **10개의 알림 규칙**이 자동으로 설정되어 있습니다.

#### Prometheus에서 Alert 확인
```
http://<node-ip>:30090/alerts
```

**자동 설정된 알림**:
- ✅ **PodDown** - 서비스 다운 2분 이상
- ✅ **HighMemoryUsage** - 메모리 90% 이상 5분
- ✅ **HighCpuUsage** - CPU 90% 이상 5분
- ✅ **HighErrorRate** - 5xx 에러율 5% 이상
- ✅ **HighLatency** - 응답시간 1초 이상
- ✅ **NodeMemoryPressure** - Worker 메모리 95% 이상
- ✅ **HighDiskUsage** - 디스크 90% 이상
- ✅ **PrometheusTargetDown** - 타겟 다운 3분
- ✅ **PrometheusNotReady** - Prometheus 다운
- ✅ **GrafanaDown** - Grafana 다운

### 2. Slack/Discord 알림 연동 (선택)

알림을 받으려면 Grafana에서 Notification Channel 설정이 필요합니다.

#### Grafana → Alerting → Contact points
1. **Add contact point** 클릭
2. **Name**: "Slack Alerts" (또는 "Discord Alerts")
3. **Integration**: Slack 또는 Discord 선택
4. **Webhook URL**: Slack/Discord에서 발급받은 Webhook URL 입력
5. **Test** 클릭하여 테스트 메시지 전송
6. **Save contact point**

#### Slack Webhook URL 발급 방법
```
1. https://api.slack.com/apps 접속
2. "Create New App" → "From scratch"
3. App 이름 입력 (예: "Biddy Monitoring")
4. Workspace 선택
5. "Incoming Webhooks" → Activate
6. "Add New Webhook to Workspace"
7. 알림 받을 채널 선택
8. Webhook URL 복사
```

#### Discord Webhook URL 발급 방법
```
1. Discord 서버 설정 → 연동
2. "웹후크" → "새 웹후크"
3. 웹후크 이름 입력 (예: "Biddy Monitoring")
4. 채널 선택
5. "웹후크 URL 복사"
```

### 3. Alert 테스트

알림이 잘 작동하는지 테스트:
```bash
# Master 노드에서 실행
```
