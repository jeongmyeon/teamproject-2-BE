## 🚨 긴급 상황별 빠른 해결

### 🔴 상황 1: Pod가 CrashLoopBackOff

#### 증상
```bash
kubectl get pods -n biddy-monitoring
```
```
NAME                          READY   STATUS             RESTARTS   AGE
prometheus-xxx-xxx            0/1     CrashLoopBackOff   5          10m
```

#### 원인 확인
```bash
# 로그 확인
kubectl logs -n biddy-monitoring prometheus-xxx-xxx --previous

# 이벤트 확인
kubectl describe pod -n biddy-monitoring prometheus-xxx-xxx
```

#### 해결 방법

**1) Alert Rules 문법 오류**
```bash
# ConfigMap 확인
kubectl get configmap -n biddy-monitoring prometheus-alert-rules -o yaml

# 문법 검증
promtool check rules /path/to/alert.rules.yml
```

**2) 스토리지 권한 문제**
```bash
# Worker 노드에서 확인
ssh worker-node
ls -la /var/lib/rancher/k3s/storage/

# 권한 수정
sudo chown -R 65534:65534 /var/lib/rancher/k3s/storage/pvc-*
```

**3) 메모리 부족 (OOMKilled)**
```bash
# 로그에서 확인
kubectl logs -n biddy-monitoring prometheus-xxx-xxx --previous | grep -i "killed"

# Swap 추가 (필수!)
ssh worker-node
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 재시작
kubectl rollout restart deployment prometheus -n biddy-monitoring
```

### 🟡 상황 2: Pod가 Pending 상태

#### 증상
```bash
kubectl get pods -n biddy-monitoring
```
```
NAME                          READY   STATUS    RESTARTS   AGE
grafana-xxx-xxx               0/1     Pending   0          5m
```

#### 원인 확인
```bash
kubectl describe pod -n biddy-monitoring grafana-xxx-xxx
```

#### 해결 방법

**1) PVC가 Bound되지 않음**
```bash
# PVC 상태 확인
kubectl get pvc -n biddy-monitoring

NAME             STATUS    VOLUME   CAPACITY   ACCESS MODES
grafana-pvc      Pending   -        -          -

# local-path provisioner 확인
kubectl get pods -n kube-system | grep local-path
```

**해결:**
```bash
# local-path provisioner 재시작
kubectl delete pod -n kube-system -l app=local-path-provisioner

# PVC 재생성
kubectl delete pvc grafana-pvc -n biddy-monitoring
kubectl apply -f k8s/monitoring/grafana.yaml
```

**2) Worker 노드 디스크 부족**
```bash
# Worker 노드에서 확인
ssh worker-node
df -h /

# 30GB 이상 여유 공간 필요
```

**해결:**
```bash
# 불필요한 이미지 삭제
sudo k3s crictl rmi --prune

# Docker 로그 정리
sudo journalctl --vacuum-time=7d
```

### 🟢 상황 3: Grafana에 "No data" 표시

#### 증상
Grafana 대시보드에서 모든 패널에 "No data" 또는 "N/A" 표시

#### 원인 확인

**1) Prometheus 연결 확인**
```bash
# Grafana → Configuration → Data sources → Prometheus
# Status: Error 또는 Unknown
```

**2) Prometheus Targets 확인**
```bash
# 브라우저에서
http://<worker-ip>:30090/targets

# 또는 kubectl
kubectl port-forward -n biddy-monitoring svc/prometheus 9090:9090
```

#### 해결 방법

**1) Prometheus 서비스 확인**
```bash
# 서비스 IP 확인
kubectl get svc -n biddy-monitoring prometheus

NAME         TYPE       CLUSTER-IP     EXTERNAL-IP   PORT(S)
prometheus   NodePort   10.43.123.45   <none>        9090:30090/TCP

# Grafana에서 Data Source URL 수정
# http://prometheus.biddy-monitoring.svc.cluster.local:9090
# 또는
# http://10.43.123.45:9090
```

**2) Spring Boot 메트릭 수집 실패**
```bash
# Pod 메트릭 엔드포인트 확인
kubectl exec -it <pod-name> -n biddy-services -- curl localhost:8080/actuator/prometheus

# 404 에러 → Actuator 미설정
# 200 OK → Prometheus 설정 문제
```

**해결:**
```yaml
# Deployment에 annotation 추가
apiVersion: apps/v1
kind: Deployment
metadata:
  name: member
  namespace: biddy-services
spec:
  template:
    metadata:
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/path: "/actuator/prometheus"
        prometheus.io/port: "8080"
```

**3) RBAC 권한 문제**
```bash
# Prometheus ServiceAccount 권한 확인
kubectl get clusterrolebinding prometheus -o yaml

# 권한 재적용
kubectl apply -f k8s/monitoring/prometheus.yaml
```

### 🔵 상황 4: 메모리 사용률 급증

#### 증상
```bash
kubectl top pods -n biddy-monitoring
```
```
NAME                          CPU(cores)   MEMORY(bytes)
prometheus-xxx-xxx            800m         1900Mi  # 2GB limit에 근접
```

#### 원인 확인
```bash
# Prometheus 쿼리 성능 확인
http://<worker-ip>:30090/graph

# 시계열 데이터 개수 확인
count({__name__=~".+"})
```

#### 해결 방법

**1) 쿼리 제한 설정 확인**
```bash
kubectl logs -n biddy-monitoring prometheus-xxx-xxx | grep -i "max-concurrency"

# 출력:
# --query.max-concurrency=10
# --query.max-samples=50000000
```

**2) 불필요한 메트릭 제외**
```bash
kubectl edit configmap -n biddy-monitoring prometheus-config
```

```yaml
# metric_relabel_configs 추가
metric_relabel_configs:
- source_labels: [__name__]
  regex: 'go_memstats_.*|process_.*'  # Go 런타임 메트릭 제외
  action: drop
```

**3) 데이터 보관 기간 단축**
```bash
kubectl edit deployment -n biddy-monitoring prometheus
```

```yaml
args:
- '--storage.tsdb.retention.time=7d'  # 15d → 7d로 단축
```

### 🟣 상황 5: Alert가 FIRING 상태인데 알림이 안 옴

#### 증상
```bash
# Prometheus에서 Alert 확인
http://<worker-ip>:30090/alerts

# PodDown: FIRING (2 active)
```

하지만 Slack/Discord에 알림이 오지 않음

#### 원인 확인

**1) Grafana Notification Policy 확인**
```bash
# Grafana → Alerting → Notification policies
# Contact point가 설정되어 있는지 확인
```

**2) Grafana와 Prometheus Alertmanager 분리**

**중요:** Prometheus에서 FIRING된 Alert는 **Prometheus Alertmanager**가 처리합니다.
하지만 현재 설정에는 Alertmanager가 없고, **Grafana Alerting**만 있습니다.

#### 해결 방법 (2가지 옵션)

**옵션 1: Grafana Alerting 사용 (권장)**

Prometheus Alert Rules를 Grafana로 이동:

1. Grafana → Alerting → Alert rules → New alert rule
2. Prometheus 쿼리 직접 입력:
   ```promql
   up{job="biddy-services"} == 0
   ```
3. Contact point 선택: Slack Alerts
4. Save

**옵션 2: Prometheus Alertmanager 추가**

```yaml
# alertmanager.yaml 생성
apiVersion: v1
kind: ConfigMap
metadata:
  name: alertmanager-config
  namespace: biddy-monitoring
data:
  alertmanager.yml: |
    global:
      slack_api_url: 'https://hooks.slack.com/services/YOUR/WEBHOOK/URL'

    route:
      group_by: ['alertname']
      receiver: 'slack-notifications'

    receivers:
    - name: 'slack-notifications'
      slack_configs:
      - channel: '#alerts'
        text: '{{ range .Alerts }}{{ .Annotations.summary }}{{ end }}'
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: alertmanager
  namespace: biddy-monitoring
spec:
  replicas: 1
  selector:
    matchLabels:
      app: alertmanager
  template:
    metadata:
      labels:
        app: alertmanager
    spec:
      containers:
      - name: alertmanager
        image: prom/alertmanager:v0.26.0
        args:
        - '--config.file=/etc/alertmanager/alertmanager.yml'
        ports:
        - containerPort: 9093
        volumeMounts:
        - name: config
          mountPath: /etc/alertmanager
      volumes:
      - name: config
        configMap:
          name: alertmanager-config
---
apiVersion: v1
kind: Service
metadata:
  name: alertmanager
  namespace: biddy-monitoring
spec:
  selector:
    app: alertmanager
  ports:
  - port: 9093
    targetPort: 9093
    nodePort: 30093
  type: NodePort
```

Prometheus에 Alertmanager 연결:
```yaml
# prometheus.yaml에 추가
alerting:
  alertmanagers:
  - static_configs:
    - targets:
      - alertmanager.biddy-monitoring.svc.cluster.local:9093
```

```bash
# Import → Change uid → (unique-id-123)
```

### 문제: Swap이 재부팅 후 사라짐

```bash
# Worker 노드에서 확인
ssh worker-node
free -h

# Swap: 0B  # ❌ 사라짐
```

**해결:**
```bash
# /etc/fstab에 자동 마운트 추가
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 확인
cat /etc/fstab | grep swapfile

# 재부팅 테스트
sudo reboot

# 재접속 후 확인
free -h
# Swap: 2.0Gi  # ✅ 정상
```

## ✅ 헬스체크 스크립트

```bash
#!/bin/bash
# health-check.sh

echo "=== Biddy Monitoring Health Check ==="
echo ""

# 1. Pod 상태
echo "📦 Pod Status:"
kubectl get pods -n biddy-monitoring
echo ""

# 2. PVC 상태
echo "💾 PVC Status:"
kubectl get pvc -n biddy-monitoring
echo ""

# 3. Prometheus Targets
echo "🎯 Prometheus Targets:"
WORKER_IP=$(kubectl get nodes -o wide | grep -v master | grep -v NAME | awk '{print $6}')
curl -s http://$WORKER_IP:30090/api/v1/targets | jq '.data.activeTargets | length'
echo " targets active"
echo ""

# 4. 메모리 사용량
echo "💾 Memory Usage:"
kubectl top pods -n biddy-monitoring
echo ""

# 5. Swap 상태
echo "🔄 Swap Status (Worker Node):"
ssh worker-node 'free -h | grep Swap'
echo ""

echo "✅ Health check completed!"
```
