### 1.3 메트릭 쿼리 테스트

Prometheus UI에서 상단 메뉴:
```
Graph
```

#### 테스트 쿼리

**1️⃣ 모든 타겟 UP 상태 확인:**
```promql
up
```
**예상 결과:** 모든 타겟이 `1` (UP) 값을 가져야 함

**2️⃣ Spring Boot 서비스 JVM 메모리:**
```promql
jvm_memory_used_bytes{application="member-service"}
```
**예상 결과:** 메모리 사용량이 바이트 단위로 표시됨

**3️⃣ HTTP 요청 수:**
```promql
http_server_requests_seconds_count
```
**예상 결과:** 서비스별 HTTP 요청 카운트

**4️⃣ 노드 CPU 사용률:**
```promql
100 - (avg by (instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```
**예상 결과:** 각 노드의 CPU 사용률 (%)

## 3. Spring Boot 서비스 메트릭 확인

### 3.1 개별 서비스 엔드포인트 확인

#### Master 노드에서 직접 확인

**member-service 예시:**
```bash
# Pod 이름 확인
kubectl get pods -n default -l app=member

# Pod에서 직접 메트릭 확인
kubectl exec -n default <member-pod-name> -- \
  curl -s localhost:8081/actuator/prometheus | head -30
```

**예상 출력:**
```
# HELP jvm_memory_used_bytes The amount of used memory
# TYPE jvm_memory_used_bytes gauge
jvm_memory_used_bytes{area="heap",id="G1 Eden Space",} 2.1234567E7
jvm_memory_used_bytes{area="heap",id="G1 Old Gen",} 1.234567E7
...
```

---

### 3.2 모든 서비스 메트릭 확인 스크립트

```bash
#!/bin/bash
# 모든 Spring Boot 서비스의 메트릭 엔드포인트 확인

SERVICES="member product order auction payment apigateway config discovery"
PORTS="8081 8082 8083 8084 8085 8000 8888 8761"

SERVICE_ARRAY=($SERVICES)
PORT_ARRAY=($PORTS)

for i in "${!SERVICE_ARRAY[@]}"; do
  SERVICE=${SERVICE_ARRAY[$i]}
  PORT=${PORT_ARRAY[$i]}

  echo "=== Checking $SERVICE (port $PORT) ==="

  POD=$(kubectl get pods -n default -l app=$SERVICE -o jsonpath='{.items[0].metadata.name}' 2>/dev/null)

  if [ -z "$POD" ]; then
    echo "❌ No pod found for $SERVICE"
  else
    echo "✅ Pod: $POD"

    # /actuator/prometheus 엔드포인트 확인
    RESPONSE=$(kubectl exec -n default $POD -- curl -s -o /dev/null -w "%{http_code}" localhost:$PORT/actuator/prometheus 2>/dev/null)

    if [ "$RESPONSE" = "200" ]; then
      echo "✅ Metrics endpoint: OK (HTTP $RESPONSE)"

      # 메트릭 개수 확인
      METRIC_COUNT=$(kubectl exec -n default $POD -- curl -s localhost:$PORT/actuator/prometheus 2>/dev/null | grep -c "^# TYPE")
      echo "✅ Metrics available: $METRIC_COUNT types"
    else
      echo "❌ Metrics endpoint: FAILED (HTTP $RESPONSE)"
    fi
  fi

  echo ""
done
```

**저장 및 실행:**
```bash
# Master 노드에서
cat > check_metrics.sh << 'EOF'
[위 스크립트 내용]
EOF

chmod +x check_metrics.sh
./check_metrics.sh
```

---

### 3.3 주요 메트릭 존재 확인

각 서비스에서 다음 메트릭이 수집되는지 확인:

#### JVM 메트릭
```bash
kubectl exec -n default <pod-name> -- \
  curl -s localhost:<port>/actuator/prometheus | grep "^jvm_"
```

**확인할 메트릭:**
- `jvm_memory_used_bytes` - 메모리 사용량
- `jvm_gc_pause_seconds` - GC 시간
- `jvm_threads_live_threads` - 스레드 수

#### HTTP 메트릭
```bash
kubectl exec -n default <pod-name> -- \
  curl -s localhost:<port>/actuator/prometheus | grep "^http_server_requests"
```

**확인할 메트릭:**
- `http_server_requests_seconds_count` - 요청 수
- `http_server_requests_seconds_sum` - 총 응답 시간

#### HikariCP 메트릭 (DB 사용 서비스만)
```bash
kubectl exec -n default <pod-name> -- \
  curl -s localhost:<port>/actuator/prometheus | grep "^hikaricp_"
```

**확인할 메트릭:**
- `hikaricp_connections_active` - 활성 커넥션
- `hikaricp_connections_idle` - 유휴 커넥션

## 6. 전체 시스템 헬스체크

### 6.1 모든 모니터링 컴포넌트 상태 확인

```bash
#!/bin/bash
echo "=== Monitoring System Health Check ==="
echo ""

echo "1️⃣ Prometheus"
kubectl get pods -n monitoring -l app.kubernetes.io/name=prometheus
echo ""

echo "2️⃣ Grafana"
kubectl get pods -n monitoring -l app.kubernetes.io/name=grafana
echo ""

echo "3️⃣ Node Exporter (DaemonSet)"
kubectl get pods -n monitoring -l app.kubernetes.io/name=node-exporter
echo ""

echo "4️⃣ kube-state-metrics"
kubectl get pods -n monitoring -l app.kubernetes.io/name=kube-state-metrics
echo ""

echo "5️⃣ Spring Boot Services"
kubectl get pods -n default -l 'app in (member,product,order,auction,payment,apigateway,config,discovery)'
echo ""

echo "=== Services ==="
kubectl get svc -n monitoring
echo ""

echo "=== NodePort URLs ==="
NODE_IP=$(kubectl get nodes -o jsonpath='{.items[1].status.addresses[?(@.type=="ExternalIP")].address}')
if [ -z "$NODE_IP" ]; then
  NODE_IP=$(kubectl get nodes -o jsonpath='{.items[1].status.addresses[?(@.type=="InternalIP")].address}')
fi

echo "Prometheus: http://$NODE_IP:30090"
echo "Grafana:    http://$NODE_IP:30300"
```

**저장 및 실행:**
```bash
cat > health_check.sh << 'EOF'
[위 스크립트 내용]
EOF

chmod +x health_check.sh
./health_check.sh
```

### 6.2 Prometheus Targets 전체 확인

```bash
# Prometheus API로 Targets 상태 확인
PROM_IP=$(kubectl get svc -n monitoring prometheus -o jsonpath='{.spec.clusterIP}')

curl -s "http://$PROM_IP:9090/api/v1/targets" | \
  python3 -m json.tool | \
  grep -E '"health"|"labels"'
```

**또는 간단하게:**
```bash
# UP 상태인 타겟 개수
curl -s "http://$PROM_IP:9090/api/v1/targets" | grep -o '"health":"up"' | wc -l

# DOWN 상태인 타겟 개수
curl -s "http://$PROM_IP:9090/api/v1/targets" | grep -o '"health":"down"' | wc -l
```

## 🔍 문제 진단 플로우

### 메트릭이 안 보이는 경우

```
1. Prometheus Targets에서 타겟 확인
   ↓ DOWN 상태?

2. Pod 상태 확인 (kubectl get pods)
   ↓ Running이 아님?

3. Pod 로그 확인 (kubectl logs)
   ↓ 에러 발견?

4. Pod 재시작 (kubectl rollout restart)
   ↓ 여전히 실패?

5. Service/Annotations 확인
   - prometheus.io/scrape: "true"
   - prometheus.io/port: "올바른 포트"
   - prometheus.io/path: "/actuator/prometheus"
```

### Grafana에 데이터가 안 나오는 경우

```
1. Grafana → Explore에서 쿼리 테스트
   ↓ 데이터 없음?

2. Prometheus UI에서 직접 쿼리
   ↓ 데이터 없음?

3. Prometheus Targets 확인
   ↓ 타겟 DOWN?

4. Spring Boot 서비스의 /actuator/prometheus 직접 확인
```
