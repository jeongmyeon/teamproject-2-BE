# 현행 구현 추적표

## 1. 조사 범위

이 문서 세트는 아래 저장소 영역을 읽어 작성했다. 설계서의 `[구현]` 판정은 이 표의 근거로 재확인할 수 있다.

| 조사 대상 | 대표 근거 | 확인 내용 |
|---|---|---|
| 모듈 목록 | `settings.gradle` | 11개 포함 모듈(Member~Search, 플랫폼) |
| 로컬 topology | `docker-compose.yml`, `init-db/01-create-databases.sql` | 포트, DB, Kafka/Redis, 환경변수 |
| Gateway | `apigateway/.../application.yml`, `JwtAuthenticationGlobalFilter` | route, CORS, 공개 경로, JWT/header |
| 서비스 설정 | 각 모듈 `src/main/resources/application*.yml` | port, datasource, AI, scheduler, Actuator |
| HTTP/STOMP 계약 | 각 `*Controller`, `WebSocketConfig`, `StompHandler` | API path, 인증 입력, WebSocket prefix |
| 도메인/DB | `domain/model`, persistence entity/repository | 상태, table, 제약, lock |
| 비동기 통합 | Kafka producer/consumer/listener, `outbox` | topic, group, 발행 방식, retry 수준 |
| 테스트 | 각 모듈 `src/test`와 `k6-tests` | 현재 자동화 범위와 공백 |
| 배포 | `.github/workflows`, `k8s`, `monitoring` | CI, image, rollout, Prometheus/Grafana |
| 기존 문서 | `docs`, `docs_codex` | 기대 문서 구조와 과거 설명 비교 |

## 2. 서비스 구현 현황

| 서비스 | 구현 확인 | 현재 주요 특징 | 설계 문서 판정 |
|---|---|---|---|
| Member | Controller/service/domain/JPA/Outbox | JWT, mail, Redis blacklist, 가입·탈퇴 이벤트 | 구현됨, 보안/Outbox 운영성 보강 |
| Product | Controller/service/JPA/Kafka/embedding | CRUD, S3, 찜, 재고 version, pgvector | 구현됨, 직접 Kafka 발행 보강 |
| Search | Controller/service/client/JPA/ES | OpenAI embedding/LLM, 이력, 추천 | 구현됨, fallback/평가/운영 endpoint 보강 |
| Auction | 3개 하위도메인/Outbox/STOMP | 비관적 lock, 1초 종료, watch cache | 구현됨, WebSocket route/다중 scheduler 보강 |
| Order | cart/order/batch/Outbox/Kafka | 일반·낙찰 주문, 재고/결제 Saga | 구현됨, 상태 권한/consumer 멱등 보강 |
| Payment | payment/wallet/settlement/Outbox | Redis 멱등/lock, Toss, ledger, 정산 | 구현됨, DB 최종 제약/대사/운영 권한 보강 |
| Chat | REST/STOMP/JPA/Redis PubSub | 1:1 방, cursor 조회, 읽음 | 구현됨, 테스트/권한/durable 정책 보강 |
| Chatbot | RAG service/Gemini/JDBC schema | 지식 markdown, vector(768), top-K | 구현됨, reingest 보호/corpus 버전/평가 보강 |
| Gateway | WebFlux filter/routes | JWT, blacklist, header 전달, Swagger | 구현됨, 경로 정합/신뢰 경계 보강 |
| Discovery | Eureka server | 단일 registry | 개발 구현, 운영 HA 결정 필요 |
| Config | native Config Server | 공통 config `{}` | 골격만 구현, 채택/제거 결정 필요 |
| Frontend | `.gitkeep`만 존재 | 내부 구조 확인 불가 | 연동 목표만 문서화 |

## 3. 코드와 기존 문서 간 주요 차이

| 항목 | 현재 코드 판정 |
|---|---|
| Auction 낙찰 이벤트 | `AuctionEndedEventProducer`가 Outbox에 저장한다. 직접 Kafka 설명은 오래됨 |
| 검색 | Elasticsearch만이 아니라 Product pgvector를 호출하는 의미 검색/LLM 재정렬 구조 |
| 챗봇 | 별도 8088 서비스와 Gemini/pgvector RAG가 존재 |
| 채팅 | 8086 REST/STOMP 및 Redis Pub/Sub 구현이 존재 |
| frontend | 저장소에 구현이 없어 React/Vite 등을 현행으로 검증할 수 없음 |
| Config Server | 서비스는 존재하나 공통 설정 원본이 비어 있어 실사용 효과가 제한됨 |
| Gateway | Search/Chat/Chatbot route가 현재 포함되지만 Chat Swagger와 Auction WS는 정합성 공백 |
| Java | CI는 Temurin 21을 사용하므로 과거 Java 17 설명을 현재 기준으로 쓰지 않음 |

## 4. 검증 한계

- 외부 DB의 실제 운영 schema와 데이터 분포는 접속하지 않았으므로 entity/schema 파일 기준이다.
- 외부 OpenAI, Gemini, Toss, S3의 실제 계정·quota·응답은 호출하지 않았다.
- 배포 중인 Kubernetes cluster 상태와 frontend 별도 저장소는 확인하지 않았다.
- 문서 작성 과정에서는 제품 코드를 변경하지 않았다. 실행 테스트는 문서 링크·구조 검증과 별도로 구분해 기록한다.

따라서 운영 환경과 다른 사실이 발견되면 이 추적표에 근거·기준일·결정자를 갱신하고 관련 설계의 `[구현]` 판정을 함께 수정한다.
