# 프론트엔드 연동 설계

## 1. 범위와 전제

현재 저장소의 `frontend/`에는 구현 코드가 없으므로 React 버전, 상태관리, 컴포넌트 구조를 현재 사실로 단정할 수 없다. 이 문서는 백엔드가 제공해야 할 연동 계약과 권장 클라이언트 구조만 정의한다.

## 2. 연결 원칙

- 브라우저는 환경별 단일 Gateway origin만 알고 개별 서비스 포트에 직접 접근하지 않는다.
- access token은 가능하면 짧은 수명과 메모리 보관, refresh token은 `Secure`, `HttpOnly`, `SameSite` cookie를 권장한다. 현재 header refresh 계약을 유지하면 XSS 위협을 별도로 완화한다.
- 모든 mutation에 명확한 loading/success/error 상태를 두며 Payment에는 UUID `Idempotency-Key`, Bid에는 client request ID를 보낸다.
- 서버가 내려준 돈 값은 정수/decimal 문자열로 다루고 JavaScript floating point 계산으로 결제 금액을 만들지 않는다.
- WebSocket 상태는 REST source of truth를 보완한다. reconnect 후 마지막 event/message ID 기준으로 gap을 복구한다.

## 3. 화면과 API 매핑

| 화면 | 주요 API/채널 | 핵심 상태 |
|---|---|---|
| 로그인/가입 | Member signup/login/email/reissue | 인증 만료, 이메일 인증 |
| 상품 목록/상세 | Product GET, like | 선택 인증, 판매 유형 |
| 검색 | Search semantic/suggestion/popular/history | AI fallback 표시 |
| 경매 상세 | Auction detail/bids/watch + auction topic | 현재가, 마감시각, 연결 상태 |
| 채팅 | Chat rooms/messages + chat STOMP | cursor, unread, reconnect |
| 장바구니/주문 | Cart/Order | 상태 전이, 만료시각 |
| 결제/예치금 | Payment/Deposit | 멱등 키, 처리중/불확실 상태 |
| 정산 | Settlement | 판매자 권한, 기간 |
| 도움말 | Chatbot query | 출처, AI 고지, 실패 fallback |

## 4. 실시간 경매 UX

클라이언트 마감 카운트다운은 서버 `endsAt`과 응답 시각을 기준으로 보정한다. BID 메시지 수신 시 `currentBid`, `bidCount`, `eventId/version`을 비교해 오래된 이벤트를 무시한다. 연결이 끊기면 “실시간 연결 끊김”을 표시하고 재연결 후 상세/입찰내역을 REST로 재조회한다. 입찰 버튼 성공 응답과 broadcast 순서는 보장되지 않는다고 가정한다.

## 5. 오류 계약

백엔드는 서비스별 제각각인 응답 대신 목표 표준을 제공한다.

```json
{
  "type": "https://biddy.example/problems/auction-not-live",
  "title": "Auction is not live",
  "status": 409,
  "code": "AUCTION_NOT_LIVE",
  "detail": "경매가 종료되어 입찰할 수 없습니다.",
  "traceId": "...",
  "fieldErrors": []
}
```

클라이언트는 HTTP status와 안정적인 `code`로 분기하고 `detail` 문구 파싱에 의존하지 않는다. 401은 한 번만 refresh를 시도하며 다수 동시 401은 single-flight로 합친다. 결제 timeout은 실패 화면 대신 “처리 결과 확인 중”으로 두고 조회/reconciliation 결과를 확인한다.

## 6. 수용 기준

- OpenAPI에서 TypeScript client와 schema를 생성하고 CI에서 breaking change를 감지한다.
- access token 만료 동시 요청이 refresh 폭주를 만들지 않는다.
- WebSocket 재연결/중복/순서 역전에도 가격과 메시지가 역행하지 않는다.
- 결제 submit 연타/새로고침에도 같은 idempotency key를 유지한다.
- 키보드 접근, focus, 색 대비, live region 등 WCAG 2.2 AA 핵심 기준을 검증한다.
