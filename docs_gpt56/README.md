## 핵심 판정 요약

현재 구현은 서비스별 DB, Eureka 기반 탐색, Gateway 인증, Kafka Saga, 일부 Transactional Outbox, Redis 멱등성/캐시, pgvector 기반 의미 검색이라는 일관된 MSA 골격을 갖춘다. 반면 운영 전에는 다음 항목을 우선 해결해야 한다.

- 외부에서 서비스 포트로 직접 접근하지 못하게 하고 Gateway가 전달하는 `X-Member-*` 헤더를 신뢰할 수 있는 네트워크 경계를 만든다.
- `ddl-auto:update`, 소스 내 개발 기본 비밀값, 공개된 디버그·배치·정산 API를 운영 프로필에서 제거한다.
- 이벤트 envelope, 버전, `eventId`, 발생시각, 생산자, 멱등 소비, DLQ/재처리 규칙을 표준화한다.
- Product의 직접 Kafka 발행과 일부 소비자의 예외 삼키기를 Outbox + 재시도/DLQ 방식으로 바꾼다.
- Gateway가 라우팅하지 않는 Auction WebSocket `/ws`와 Swagger의 Chat 누락 등 실제 연결 계약을 정합화한다.
- 단일 PostgreSQL·Kafka·Redis·Eureka 구성을 운영 HA 구성으로 분리하고 SLO 기반 알림을 도입한다.
